                    What Millix is
                    
        
                    
          Millix is an open-source, peer-to-peer cryptocurrency built for speed, scale, and small payments.
          It is not Bitcoin. It is not Ethereum. It is not an ERC-20. Development started in 2018.
          The genesis event was 20 January 2020. All Millix that will exist was created then — it is not mined,
          and millix.org does not sell it. Buy and sell on
          millix.com
          and other exchanges that list MLX.
        
                    
        
                    
          Every node has the same authority. There is no miner caste and no validator hierarchy.
          A node is any device running the Millix software — laptops, servers, even low-power boards.
          Transaction fees go to a randomly chosen proxy node, not to a mining pool.
          Fiat value on this locker uses the fiatleak peg printed on the enter page:
          1,000,000 MLX = $0.18.
        
                    
      
                    

      
                    
        
                    What a DAG is
                    
        
                    
          DAG means directed acyclic graph. Directed: every edge has a direction, like time.
          Acyclic: those edges never loop back to form a cycle. Graph: many nodes, many paths, not one chain of blocks.
          Millix also calls this a tangle. Data can fan out along several branches at once, so capacity can rise
          as more nodes join instead of waiting on a single block producer.
        
                    
        
                    
          A blockchain is one ordered stack of blocks. A DAG is a one-way mesh. You do not need the entire graph
          on every machine. Millix shards transaction data across nodes. Each node is obliged to keep its shard,
          not a full copy of history. Older settled transactions hibernate so the working set stays small.
        
                    
      
                    

      
                    
        
                    How a transaction moves
                    
        
                      
          
                    1. A sender builds a transaction and a random node is picked as proxy.
                      2. 
          
                    2. The proxy checks history: funds exist, no double spend. If it lacks a record, it asks peers.
                      3. 
          
                    3. If valid, the proxy fans the transaction out. Peers validate on their own and compare answers.
                      4. 
          
                    4. Once consensus holds, the transaction stabilizes. After about ten minutes it hibernates — resting, not rewritten.
                      5. 
          
                    5. The proxy keeps the fee the sender attached. The sender sets the fee; the wallet can suggest one from recent traffic.
                      6. 
        
                    
        
                    
          Trust is not “everyone has the same full ledger.” Nodes ask several random peers and compare what they hear.
          That is the millix.org design: pick a random node, request, repeat, compare.
